## Задачи

### DASH-601 — Сессия Mini App: переоткрытие при истечении cookie

- **Статус:** `done` · **Приоритет:** P0 · **Оценка:** M · **Область:** frontend/auth
- **Зависит от:** —
- **Почему:** app/api/control/session/route.js существует, но клиент его не вызывает. Через 30 минут cookie протухает — панель показывает «Необходим вход через Telegram» и умирает до перезапуска.
- **Как сделано:** `lib/control-client.js`: `controlFetch` при 401 пересоздаёт сессию через `POST /api/control/session` и повторяет исходный запрос один раз; `control-client.test.js` покрывает 401 → refresh → retry.
- **Готово, когда:**
  - [x] После 30+ минут панель молча продлевает сессию
  - [x] При отказе в доступе пользователь видит понятное сообщение, а не белый экран
  - [x] Тест на 401 → refresh → retry

### DASH-602 — Серверные тесты маршрутов /api/control/*

- **Статус:** `done` · **Приоритет:** P0 · **Оценка:** M · **Область:** backend/tests
- **Зависит от:** —
- **Почему:** Сейчас покрыты только payloadFor и HMAC. Сами роуты (enqueue, консент nonce, отмена) не тестируются, а UI уже от них зависит.
- **Как сделано:** `src/__tests__/control-api-routes.test.js`: route-хендлеры вызываются напрямую с Request; Supabase замокан через fetch-стаб в Node-окружении Vitest.
- **Готово, когда:**
  - [x] 401 без сессии, 400 на неверный kind/mode
  - [x] LIVE без nonce отклоняется
  - [x] Повторный idempotency_key возвращает idempotent: true

### DASH-603 — Псевдонимы аккаунтов на сервере

- **Статус:** `done` · **Приоритет:** P1 · **Оценка:** S · **Область:** fullstack/privacy
- **Зависит от:** `DASH-602`
- **Почему:** control/policy.py::Redactor.redact_account_name выдаёт «Аккаунт N», но bootstrap и /api/control/commands отдавали сырое name (main, work2).
- **Как сделано:** `lib/account-aliases.js` — детерминированная карта `acc-N` → внутреннее имя; bootstrap отдаёт `account_aliases` и строки с `key`/`display_name`; маршруты транслируют key → имя перед enqueue (внутренние имена принимаются для совместимости); списки команд отдают `account_display`.
- **Готово, когда:**
  - [x] В сетевой панели браузера нет main/work2
  - [x] Выбор аккаунта в форме работает по key
  - [x] Плановый тест на отсутствие внутренних имён в ответе

### DASH-607 — Веб-консоль воркера: состояние онлайна

- **Статус:** `done` · **Приоритет:** P2 · **Оценка:** M · **Область:** frontend
- **Зависит от:** —
- **Почему:** Панель не говорит, жив ли воркер: команды висят в PENDING и пользователь не понимает, что происходит.
- **Как сделано:** таблица `tb_worker_heartbeat`, `QueueRepository.heartbeat()` в каждом тике воркера; bootstrap отдаёт `worker {last_heartbeat_at, online, stale_seconds}`; бейдж в шапке через `lib/worker-status.js`; порог `WORKER_STALE_SECONDS` (по умолчанию 600 = 2× аренды).
- **Готово, когда:**
  - [x] Офлайн-воркер виден на первом экране
  - [x] Порог — настраиваемый, по умолчанию 2 интервала lease
