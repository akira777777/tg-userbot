# Руководство tg-userbot

Личный аккаунт Telegram (Telethon): сбор участников групп в SQLite, рассылка в чаты и в личку, несколько аккаунтов на одной базе.

Каталог на этой машине: `C:\Users\novra\Desktop\tg-userbot`.  
Интерпретатор: `.\.venv\Scripts\python.exe` (Python 3.14). Системный `python` не использовать.

Точки входа: `bot.py` (CLI), `web.py` (панель), при необходимости `python -m control.main` (Mini App). Пакета `src.tg_userbot` нет.

## Типовой день

1. `bot.py status` — очередь и паузы аккаунтов.
2. Разведка, ничего не уходит в Telegram:
   ```
   bot.py broadcast --text "…" --dry-run
   bot.py dmsend --file msg.txt --limit 10 --dry-run
   bot.py conduct --what dm --text "…" --limit 10 --dry-run
   ```
3. Живая отправка — только после dry-run, с лимитом и паузами по умолчанию.
4. Новая группа: `groups --sync` или держать `watch`.
5. Права писать: `groups --probe --keep` (только показ) или без `--keep` (снимет недостижимые с рассылки). Для каждого аккаунта отдельно.

Полный цикл: `groups --sync` → `scrape` → `status` / `export` → `--dry-run` → `broadcast` или `dmsend`.

## Кого не слать

**Личка (`dmsend`, `conduct --what dm`).** Очередь одна и та же в CLI и в `dm_available` панели (`DM_ELIGIBLE_WHERE`):

- бот (флаг Telethon или ник оканчивается на `bot`; `Subbotina` / `Rabota` остаются);
- удалённый аккаунт;
- нет username и нет `access_hash`;
- постоянный отказ `dm_block` (закрытая личка, блок, …);
- blacklist;
- уже успешный DM любым аккаунтом (снять: `--repeat-ok`);
- свой id.

Пустые профили из таблицы не чистятся. Без ника и хеша писать некуда. Хеш только фильтр очереди: в отправку идёт `user_id`. Хеш чужому аккаунту не подставляется.

**Группы (`broadcast`, `conduct --what broadcast`).** Чат в рассылке, только если хоть один аккаунт может писать:

- канал-подписчик без права постить — не цель; создатель или админ с `post_messages` — цель;
- выход, кик, личный мут, запрет сообщений всем — не цель;
- куда успешно писали меньше 24 ч назад — пропуск (снять: `--repeat-ok`);
- slowmode длиннее окна `conduct` — пропуск без попытки.

`sync` и `watch` чат запоминают, в `in_broadcast` ставят только если писать можно.

## Чтобы меньше резали аккаунт

Решение слать — на операторе. Инструмент только тормозит.

- DM: `--limit 20`, паузы 20–45 с, дневной бюджет 30 (`accounts budget`). Паузы не укорачивать.
- Группы: паузы 3–8 с, дневной потолок 15 (`accounts bbudget`).
- `FloodWait` и `FloodPremiumWait`: аккаунт на паузу на время сервера. Текущая цель остаётся ему **внутри этого процесса** `conduct` (в SQLite не пишется). После Ctrl+C следующий запуск раскладывает очередь заново. Ещё не взятые цели в том же запуске могут взять другие аккаунты. Slowmode одного чата аккаунт целиком не останавливает.
- `PeerFlood` / ограничение аккаунта: пауза 24 часа, эта кампания аккаунта стоп. Очередь DM другим не отдаётся. Цель не помечается мёртвой.
- Постоянный отказ цели запоминается и больше не выбирается.
- Сначала 5–10 живых сообщений и пауза на день-два. Текст: кто вы и «ответьте СТОП». `watch` занесёт «стоп / stop / отпишись» в blacklist.

## Команды

Общий вид: `.\.venv\Scripts\python.exe bot.py <команда> [--account main]`.

| Команда | Сеть Telegram |
| --- | --- |
| `login` | да |
| `groups --sync` / `--list` / `--probe [--keep]` | sync и probe — да |
| `watch [--noreply]` | да, висит |
| `scrape [--groups …]` | да |
| `broadcast` / `dmsend` / `conduct --what dm\|broadcast` | да |
| `privacy` / `align` / `compare` | да |
| `media add\|pull\|sync` | да; `list`/`del` — нет |
| `export` / `status` / `blacklist` / `accounts` | нет |
| `cloud push\|status\|test` | Supabase, не чаты |

Справка: `bot.py --help`.

### groups

```
bot.py groups --sync
bot.py groups --list
bot.py groups --probe [--keep] [--account main]
```

`--probe` без `--keep` снимает с рассылки чаты, куда этот аккаунт писать не может. Право уникально для пары аккаунт×группа. Дирижёр берёт того, у кого `can_write`.

### watch

Первое сообщение из новой группы → в список (если можно писать — в рассылку). «стоп» в личке → blacklist. Ctrl+C — выход.

### scrape

Участники в `members`. Повторно докачивает новых. FloodWait >10 мин — стоп с сохранением. Закрытый список (не админ канала) — пропуск группы. Агрессивный обход участников выключен.

### broadcast / dmsend

```
bot.py broadcast --text "…" [--file msg.txt] [--media ID] [--ids …] [--dry-run]
bot.py dmsend --text "…" [--file msg.txt] [--media ID] [--group ID] [--limit 20] [--dry-run]
```

Пауза DM короче 10 с (`dmsend` и `conduct`) печатает предупреждение. `--media` — id из `media list`, текст уходит подписью.

### accounts / conduct

```
bot.py accounts list
bot.py accounts budget work2 30
bot.py accounts bbudget work2 15
bot.py login --account work2
bot.py conduct --what dm|broadcast --text "…" [--dry-run] [--limit N] [--window 6]
```

Одна база: цели, журнал, blacklist, бюджеты. Один session-файл = один процесс. Импорт сессии копирует файл; тот же файл второй раз не принимают.

### media

Файл в «Избранное» аккаунта и в `media_cache/`. `add` / `pull` / `sync` / `list` / `del`.

### privacy / align / compare

`privacy` — Nobody по ключам API (после `login` новым аккаунтам). Скрытый last seen: вы тоже не видите чужой точно.  
`align` — догон публичных групп + privacy + probe, лимит вступлений за запуск.  
`compare --other main` — покрытие и приватность двух аккаунтов.

## Панель

```
.\.venv\Scripts\python.exe web.py
```

Порт `WEBBOT_PORT` (8642). Хост по умолчанию `WEBBOT_HOST=0.0.0.0`; в браузере открывайте http://127.0.0.1:8642.

Dry-run в формах включён по умолчанию. Одна задача на аккаунт (слот сессии). Fanout «всем» — sync/scrape/watch/probe/privacy/align. Стоп адресный.

## Облако и Mini App

`cloud push` — агрегаты в Supabase (`tb_*`), ники людей не уходят. `AUTO_CLOUD=1` — после части команд. Ключи в чат не копировать.

Дашборд: каталог `dashboard/`, вход `DASH_TOKEN`. Тесты: `npm --prefix dashboard test`. Деплой: `cd dashboard && vercel deploy -y`.

Mini App не запускать, пока в `.env` нет своих `MINI_APP_URL` (https), `OWNER_TELEGRAM_IDS`, `BOT_TOKEN`, длинного `CONTROL_SESSION_SECRET`. `docker-compose.prod.yml` без этих переменных worker/controller не стартует. Воркер умеет вызвать `bot.py` и дойти до живого аккаунта.

## Если сломалось

| Симптом | Что делать |
| --- | --- |
| `ModuleNotFoundError: telethon` | `.venv\Scripts\python.exe`, не системный Python |
| нет API_ID | `.env` из `.env.example` |
| сессия не авторизована | `bot.py login [--account …]` |
| FloodWait / PeerFlood в логе | не слать с этого аккаунта до конца cooldown; DM-очередь другому не отдавать |
| панель и `status` расходятся по DM | перезапустить `web.py` |
| группа вне рассылки «без причины» | `groups --probe --keep`, не включать вручную вслепую |
| `make` / старый FastAPI | этого стека нет; только `bot.py` / `web.py` |
| `scripts/` просят Postgres, Redis или Alembic | этого стека нет. `healthcheck.py`, `backup.py` и `db-migrate.py` работают с SQLite (`USERBOT_DB`). Сессии скрипты не копируют |

Ответственность за текст и выбор целей — на владельце аккаунта.
